- `config/check_items.yaml`：45 项目录（只读名称/分组/模式）

## 二、线上行为

1. 一帧图片进入 worker 后，不再只问“6 类里有没有隐患”，而是对 9 个试点子项**各调用一次**模型。
2. 每个子项独立产出一条 `HazardEvent`：
   - `hazard_type = "CI-06/6.11"` 这种“检查项/子项”格式
   - 新增 `check_item_code`、`sub_item_code`、`check_item_name`、`detection_mode`
   - 有缺陷 → `is_hazard=true`，强制人工复核
   - 不可判定 → `is_hazard=false`，`need_manual_review=true`，理由以 `[不可判定]` 开头
   - 模型失败/解析失败 → 生成降级事件，保留整图证据，强制人工复核
3. 没有隐患的负向结论也会入库（`is_hazard=false`），用于审计；看板默认只显示 `is_hazard=true`。
4. 旧 `HZ-01..06` 链路保留：关闭试点后行为与之前完全一致。

## 三、开关与成本

```bash
# 默认开启（config/pilot_check_items.yaml enabled: true）
# 关闭试点，回到旧 4 类：
CHECK_ITEMS_PILOT=false
```

- 单帧最多 **9 次**模型调用（`max_calls_per_frame: 9`）
- 子项内部并发 **4**（`concurrency: 4`）
- 一帧 9 个子项全部成功，帧状态才是 `done`；任一失败则帧 `failed`，但已成功的事件仍会保留
- 试点不注入点位上下文；提示词明确“图片可能带人工标注/水印，不要把标注当判据”

## 四、API 变化

### `GET /api/v1/health`

新增：

```json

  "check_items_pilot": true,
  "check_items_count": 9

```

### `GET /api/v1/config`

新增：

```json
{
  "check_items": {
    "enabled": true,
    "version": "2026-11-08.pilot.1",
    "prompt_version": "pilot-v1",
    "max_calls_per_frame": 9,
    "items": [
      {
        "code": "CI-06",
        "name": "法兰",
        "group": "设备与管道",
        "detection_mode": "vl_closeup",
        "enabled": true,
        "sub_items": [{"code": "6.11", "name": "..."}]
      }
    ]
  }
}
```

### `GET /api/v1/tasks/{id}`

每个 frame 新增 `events` 数组；旧的 `event` 字段保留：

- `event`：第一条隐患（没有隐患则第一条结论）
- `events`：该帧全部 9 条结论

### 事件字段

`GET /api/v1/events`、`GET /api/v1/events/{id}` 新增：

```json
{
  "check_item_code": "CI-06",
  "sub_item_code": "6.11",
  "check_item_name": "法兰/法兰螺栓或螺母松动、缺失或腐蚀生锈",
  "detection_mode": "vl_closeup"
}
```

## 五、数据库

`events` 新增 4 列（老库自动迁移，不删数据）：

```
check_item_code VARCHAR(64)
sub_item_code   VARCHAR(32)
check_item_name VARCHAR(128)
detection_mode  VARCHAR(32)
```

迁移在 `db.init_db()` 里做：先 `create_all`，再 `PRAGMA table_info`，缺列就 `ALTER TABLE ADD COLUMN`，并补索引。
