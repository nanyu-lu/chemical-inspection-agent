## 二、P0：必须先处理

### 1. 94 张图不是“现场实拍”，而是带红圈/水印的公众号插图

- 我抽看了 6.11 / 6.13 / 11.1 三张图：都有**手绘红圈**，右下角统一水印「公众号：回忆里放逐」。
- 报告自己也写了：`baseline_分析.md` 第 28 行明确说“并非现场实拍，数据来源与许可证台账应据此更正”。
- 但 `README.md` 第 154 行仍写“原始 94 张现场图”，`docs/网上数据源与许可证.md` 也写“现场第一批”，口径冲突。
- **风险**：
  - 这批图没有本地许可证台账；若来自公众号文章，不能默认可用于训练/交付。
  - 红圈等于把缺陷位置先验交给模型；6.11 的 100% 是上限，不是自主发现能力。
  - 对外交付时，“现场照片”的来源声明不成立。

**建议**：

1. 把目录/文档改名为“网络公开图第一批（带红圈/水印）”，不要叫“现场第一批”。
2. 新增 `data/datasets/local/45项/PROVENANCE.md`：来源链接、获取日期、版权状态、仅内部评测声明。
3. 在拿到无标注现场图前，这批数据只用于“确认能力”与“回归”，不作为验收指标。
4. 对外交付前，替换为有授权的现场图，或删除这批派生评测。

### 2. 没有负样本，不能报精确率/误报率

- 现有 94 张全部是“已确认缺陷图”，只能算召回。
- 报告已明确说明，但 `README` 的“一分钟看结论”仍需加一句“无负样本，不算误报”。
- `bolts-and-washers` 是最重要的负样本来源，目前 Kaggle 目录仍为 0。

### 3. 红圈导致 6.11 的 100% 不可外推

- 报告已量化：6.11 22/22 带圈、6.13 9/9、6.9 6/8、CI-11 22/25；19%（12/64）证据文本直接写“红圈”。
- 结论应写成“带标注确认能力 100%”，不要写成“法兰螺栓检测召回 100%”。

## 三、P1：口径/配置需要修正

### 4. 计数口径不一致

报告里同时出现：

- “manifest 94 行，去重后 **87 张参与**”
- “**4 组 87 张，89 次调用**”
- 但 per_sub 实际是 **22 + 9 + 8 + 25 = 64 张**；CI-11 merged 复用 25 张，才得到 89 次调用。

**建议**加一张核对表：

| 口径 | 数量 |
|---|---|
| manifest 行数 | 94 |
| 唯一 sha1 | 87 |
| 4 组 per_sub 实际计分 | 64（6.11 22 + 6.13 9 + 6.9 8 + CI-11 25） |
| CI-11 merged 复用 | 25 |
| 总调用 | 89 |

另外，6.11 的 manifest 是 25 张，CSV 是 22 张，少的是 3 张重复图：

```
07_05_13c328.jpg  = 06_08_13c328.jpg
07_12_24ead3.jpg  = 07_11_24ead3.jpg
07_14_e9c9c.jpg   = 06_05_e9c9c.jpg
```

报告应写明“25→22 是去重，不是漏跑”。

### 6. Prompt 里写了“现场巡检实拍图”，与事实不符
