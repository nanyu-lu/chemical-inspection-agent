## 4. 执行中发现的问题

1. **第一批 94 张图普遍带人工红圈**（6.11 100%、6.13 100%），水印统一为「公众号：回忆里放逐」。模型证据文本反复写"红圈内"，说明它用上了这个先验。因此当前召回是**上限**，不等于自主发现能力。口径需在报告里写清。

2. **CI-11 单子项 40% 的 9 例漏检里，7 例是模型忠实执行了我写宽了的判据**（"有金属堵头即合规"）。这是判据边界问题，不是模型能力问题。

3. **三处编号归属不一致**（已写入 `sub_items_catalog.yaml` 的 `known_mismatches`）：
   - `3.14` 图片归 CI-01，目录里属 CI-03；
   - `11.5` 图片归 CI-26 电缆布设，目录里属 CI-11；
   - CI-05 有 `5.9/5.10` 图片，但清单呼吸阀只到 `5.8`，**缺判据文本**。

4. **文档 §10 的计数命令会高估**：`find data/datasets/web ... -name '*.jpg'` 会把 `raw/hf-bolt-screw-synthetic` 的 993 张算进去，实测 1060，而预期应为 74/67。候选数请用 `negative + missing + share_alike` 分目录统计。

5. **沙箱环境有两个坑（非项目 bug）**：
   - `mkdir(exist_ok=True)` 在已存在目录上被代理误判为 `FileExistsError`，已把 `fetch_web_samples.ensure_dirs()` 改为先 `is_dir()` 判断；
   - pytest 用默认 `/var/folders` 临时目录会报同样错误，用 `TMPDIR=/tmp/... uv run pytest -q` 可正常 35 passed。
